## Результат перевірки 16.11.2026

Усі 20 запитань надіслано через вебчат із трьох окремих облікових записів. До зупинки викликів моделлю отримано п’ять відповідей із джерелами (F1, F2, F3, P1, P2). F4, S2 і T3 відкрили уточнення про товари, а P4 додатково запустило непотрібний пошук залишків. Після двох запитів з невідомим результатом шлюз зупинив генерацію, тому відповіді моделі для решти запитань не підтверджені.

Після виправлення маршрутизації й повторної публікації статей усі 20 запитань під відповідними ролями скеровуються лише до бази знань. Для кожного запитання перевірено, що працівник може відкрити потрібну статтю і що Векторія отримує всі її кроки. Раніше запитання T2 знаходило правильну статтю, але в уривку бракувало початку з назвою документа й типом операції. Повторна перевірка тексту відповідей потребує відновлення генерації.

У першому запуску F1 правильно пояснило пошук за номером. Для F2 відповідь описала розширений фільтр, хоча в списку вже є поле «Клієнт». Для F3 бракувало назви «Дата проведення». P1 і P2 правильно назвали шлях від замовлення до надходження. В оновленій статті для часткового приймання вказано точне поле «Прийнята кількість».

У робочому інтерфейсі перевірено пошук чернетки за номером, перемикання кнопки з «Провести» на «Зберегти» після редагування, створення незбережених накладної й надходження з проведених замовлень та звіт «Перегляд» → «Рух товарів». Для часткового приймання редагується «Прийнята кількість». У рядку замовлення постачальнику підсумок можна переглянути в полі «Отримана кількість». Для тестування не проводили робочих документів. Після перевірки три тимчасові облікові записи вимкнено й їхні сеанси закрито.
