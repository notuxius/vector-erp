# Telegram-бот MTech: MVP для продажів і підтримки

Помилки й пропозиції щодо Вектор ERP працівники можуть надіслати у вебчаті Векторії кнопкою **Адміністратору**. Звернення й аналіз Codex доступні адміністратору в ERP. У Telegram клієнти, як і раніше, можуть обрати **Написати менеджеру**.
Якщо ШІ бази знань недоступний, у вебчаті кнопка **Надіслати адміністратору** під повідомленням одразу надсилає звіт про збій. Після надсилання звіту або звернення через форму **Адміністратору** ERP показує «✓ Адміністратор отримав ваше звернення.», номер звернення й кнопку **Оновити**.
Після відповіді Векторії можна одразу надіслати наступне запитання. Вебчат і приватний Telegram власника мають спільний ліміт у 100 запитань за останні 60 хв.
У формі звернення до адміністратора оберіть **Пропозиція** або **Помилка**. Можна надіслати лише контекст, без повідомлення. Щоб переглянути чи змінити уривок чату, розгорніть **Контекст для аналізу**. Автоматичні звіти містять час збою, версію вебчату й умови його роботи для аналізу Codex.

Меню ERP у приватному чаті власника читає залишки та дозволені статті із
Вектор ERP на Contabo VPS 6. Вебхук Telegram і далі обслуговує Cloudflare.

У приватному чаті власника відкрийте **/ai** (Векторія ✦ ШІ-помічник) і запитайте «Що мені сьогодні відвантажувати?». Помічник підкаже, де відкрити звіт у Вектор ERP і як вибрати дату. Для приймання, переміщення та відвантаження можна так само запитати про послідовність дій. Фактичний список замовлень працівник переглядає у Вектор ERP зі своїми правами.

Для власника в приватному чаті з увімкненим ШІ-пілотом доступна **/usage** — залишок спільного з вебчатом ліміту, час наступного запитання, бюджет ШІ та ліміти OpenAI і Cloudflare. Команда працює також поза розмовою з помічником. [Опис звіту](telegram-ai-pilot.uk.md).

Власник може відкрити **/ai** у приватному чаті й натиснути готове запитання. У розділах **Залишки та база знань** і **Чернетка відповіді клієнту** є по 20 тем із такими самими короткими назвами, як у вебпомічнику. На сторінці видно 10 тем. Натисніть коротку назву теми один раз. Наприклад, якщо обрати **Лінзи f-50 і f-75**, бот одразу опублікує в чаті «Чим відрізняються фокусувальні лінзи f-50 і f-75?» і покаже «🤖 Готую відповідь…», поки готує відповідь. Також можна ввести власне запитання. Відповідь з’являється під запитанням. Вебпомічник і бот використовують спільний перелік запитів про каталог, залишки, навчальні операції та чернетки клієнту. Повернутися до переліку можна кнопкою **Готові запитання**. Для перевірки навчальна інструкція містить очікувані відповіді. [Приклади у Вектор ERP](ai-chat.uk.md#навчальні-запитання)


Запит про залишок звертається лише до ERP, про характеристики чи порядок дій — до бази знань. Для змішаного запитання бот показує обидві частини. Якщо написати тільки назву товару, можна обрати «Залишок» або «Характеристики» для цієї позиції.

У приватному чаті власника під час пошуку в ERP або підготовки відповіді
Векторії бот оновлює індикатор «друкує…» після показу запитання й далі приблизно кожні півтори секунди. Коли відповідь з’являється в чаті окремим повідомленням, Telegram прибирає індикатор.
Після відповіді власник може написати наступне запитання без /ai. Щоб вийти,
натисніть «Завершити» під відповіддю або відкрийте /menu.

З 05.11.2026 Векторія у приватному чаті власника використовує локальний бюджет Вектор ERP. Підтверджувати фінансування API чи подовжувати строк кредиту не потрібно. Шлюз сповіщає власника на 75% та 95% і зупиняє запити, які перевищили б межу 95%. Пошук залишків за фільтрами працює незалежно від моделі.

## Передача запитання менеджеру

Підготовлено 05.11.2026 для Worker і локального бота. Коли бот отримує запитання поза сценарієм, він пропонує «Замовити дзвінок» або «Написати менеджеру». Ці дії також доступні в «Контактах». Приватний клієнтський запит через `/ai` або `/erp` поза формою потрапляє до того самого сценарію. ШІ ERP доступний лише власнику.

Текст запитання до 700 символів підставляється в чернетку. Перед надсиланням клієнт може змінити його або скасувати заявку. Для письмової відповіді достатньо тексту. Для дзвінка бот запитує або підставляє з профілю ім’я, телефон і зручний час. Після підтвердження клієнт отримує номер заявки.

Менеджери працюють у будні з 08:00 до 17:00 за Києвом. Після завершення робочого дня та у вихідні в повідомленні є посилання на відкритий каталог MTech, доставку й оплату, гарантію та повернення. Сторінка за темою запитання з’являється першою. Відкриття посилання не створює заявки.

У приватному чаті працівника довідка `/help` також пояснює команду відповіді. У сповіщенні про письмову заявку команда отримує підказку `/reply 123 текст відповіді`. Замість `123` підставте номер із повідомлення. Команда працює лише в налаштованому чаті працівників, з особистого акаунта учасника. Бот бере адресу клієнта із збереженої заявки і додає відповідь до черги Telegram. Підтвердження менеджеру означає, що відповідь у черзі. Невдалу доставку можна перевірити у звичайному журналі черги. Команда приймає до 1500 символів і діє лише для письмових заявок.

Для локального запуску Python потрібні часові дані IANA для `Europe/Kyiv`. У Windows встановіть `python -m pip install tzdata` в робочому віртуальному середовищі. Образ Docker включає цей пакет.

## Що реалізовано

| Розділ | Поведінка |
|---|---|
| Обладнання | Сім категорій із прямими посиланнями; запит щодо моделі, ціни, наявності чи комплектації |
| Комплектуючі | Вісім швидких категорій, повний каталог, заявка з описом, кількістю та фото |
| Допомога з вибором | Завдання, матеріал, розміри, необов’язкові бюджет і побажання |
| Сервіс і підтримка | Несправність, налаштування/навчання, гарантія, повернення/обмін, питання щодо замовлення |
| Доставка та оплата | Підготовлені відповіді про доставку, самовивіз та оплату; посилання на повні умови |
| Контакти | Телефони без суперечливих підписів відділів, адреса, години роботи, заявка на дзвінок |
| Статус заявки | До 10 останніх власних заявок у боті: номер, дата, тема й поточний статус; оновлення та запит менеджеру щодо замовлення або сервісних робіт |
| Новини та пропозиції | Добровільна підписка на новини, нові послуги, акції та спеціальні пропозиції; явні кнопки підписки та відписки |

Усі дванадцять сценаріїв звернень використовують збережені ім’я, телефон і зручний час дзвінка. Бот запитує лише відсутні контактні дані; на наступних зверненнях одразу переходить від деталей запиту до перевірки заявки. Кнопка «Мої дані» в головному меню та на перевірці дозволяє змінити окреме контактне поле. Зміна потрапляє в поточну чернетку та наступні заявки; вже надіслані заявки залишаються незмінними. Клієнт також може змінити деталі заявки, повернутися назад або скасувати чернетку. До заявки можна додати до трьох фото. Стара кнопка не змінює поточний крок; повторне надсилання не створює другу заявку.

Таблиця `customer_profiles` зберігає лише ім’я, телефон і зручний час за Telegram ID приватного чату. Перевірені значення зберігаються одразу після введення й залишаються після скасування, очищення семиденних чернеток та перезапуску. Власний контакт, надісланий поза чернеткою, також зберігається: ім’я з картки використовується лише за відсутності раніше вказаного імені. Чужі контакти та некоректні телефони відхиляються. Тексти запитів, моделі обладнання, фото та інші деталі заявок не переносяться в профіль.

Перед першим розгортанням із профілями застосуйте `0002_customer_profiles.sql` після резервної копії D1. Міграція додає таблицю й відновлює останнє надане значення кожного контактного поля з наявних заявок та чернеток. Вона не змінює ці записи й не перезаписує вже створені профілі при повторному запуску. Python-сервіс виконує еквівалентний `services/telegram_bot/profiles.sql` під час відкриття бази.

Поза сценарієм довільний текст можна перенести до загального запиту. Голосові повідомлення не розпізнаються. Групові повідомлення не запускають клієнтські сценарії. Розділ статусів показує лише заявки поточного Telegram-акаунта; чужий номер не відкриває чужі дані. Статуси `new`, `in_progress`, `closed` показуються як «Зареєстровано», «В опрацюванні», «Закрито». Це статус опрацювання звернення, а не оплати, доставки чи ремонту в ERP. Для фактичного стану замовлення або сервісних робіт є окремий сценарій уточнення в менеджера з необов’язковим номером замовлення / сервісної заявки.

Підписка вимкнена за замовчуванням. Відкриття розділу `/news`, подання заявки чи обмін контактом не означає згоди. Лише кнопка «Підписатися» записує згоду для цього Telegram-чату. «Відписатися» вимикає її. Таблиця `subscriptions` містить Telegram ID, поточний стан, час останнього вибору UTC і версію тексту згоди `mtech-news-v1`; вона не очищається разом із семиденними сесіями. Зміна тексту згоди потребує нової версії. Розсилання кампаній поки не реалізовано: майбутній механізм має перевіряти чинну підписку безпосередньо перед надсиланням. Ці зміни самі не надсилають рекламних повідомлень.

## Локальна перевірка без Telegram

Потрібен Python 3.11 або новіший. Сторонніх Python-пакетів немає. Команди виконуються з кореня репозиторію.

```powershell
python -m unittest services.telegram_bot.test_bot -v
python -m services.telegram_bot simulate
```

Симулятор використовує справжній обробник сценаріїв із тимчасовою базою в пам’яті. Введіть `/1`, `/2` тощо для натискання кнопки або текст відповіді. Звичайні числа залишаються текстовими відповідями, наприклад кількістю товару. `/photo` додає тестове фото; `/quit` завершує сеанс. Дані симулятора не надсилаються в Telegram і зникають після виходу. У симуляторі контактна кнопка використовує вигаданий номер.

## Попередній локальний режим: підключення Telegram

1. Створіть окремого бота MTech через [BotFather](https://t.me/BotFather). Збережіть токен у локальному файлі `.env.telegram`.
2. Підготуйте приватний чат відповідального працівника або закриту групу команди. Для приватного чату працівник спочатку має натиснути Start у боті; до групи потрібно додати бота й дозволити йому надсилати повідомлення та фото.
3. Вкажіть числовий ID цього чату в `TELEGRAM_STAFF_CHAT_ID`. Для групи ID зазвичай від’ємний. ID можна взяти з `message.chat.id` власного тестового оновлення Bot API; не надсилайте приватні дані стороннім ботам для його визначення.
4. Виконайте перевірку налаштувань і запустіть сервіс.

Приклад файлу: `services/telegram_bot/.env.example`. Якщо локального `.env.telegram` ще немає:

```powershell
Copy-Item -LiteralPath services/telegram_bot/.env.example -Destination .env.telegram
```

Не перезаписуйте файл, якщо він уже містить налаштування. Його вміст:

```dotenv
TELEGRAM_BOT_TOKEN=токен-від-BotFather
TELEGRAM_STAFF_CHAT_ID=числовий-ID-чату-команди
TELEGRAM_DATABASE=data/telegram/bot.sqlite3
```

Токен не потрібно надсилати в чат або додавати в Git. `.env.telegram` та локальна база в `data/` виключені з Git. Змінні середовища процесу мають пріоритет над файлом.

```powershell
python -m services.telegram_bot check-config
python -m services.telegram_bot check-config --online
python -m services.telegram_bot run
```

`check-config --online` лише перевіряє Telegram-акаунт, відсутність активного webhook і доступ до чату команди. Він не надсилає повідомлень. Під час `run` налаштовуються українські команди бота для всіх мов Telegram та окрема стандартна кнопка меню біля поля повідомлення, після чого запускається long polling. Кнопка відкриває список команд із «Головне меню» (`/menu`) першим пунктом; її вигляд, підпис і точне розташування залежать від клієнта Telegram. Вхідний порт, публічний домен і HTTPS-сервер для цієї версії не потрібні.

У меню завжди доступні `/menu`, `/status`, `/news` та `/help`, навіть без заявок або підписки. Підписка керує доступом до публікацій та згодою на розсилання, але не видимістю команд. Поточна версія меню — 5. Підписатися можна через кнопку «Новини та пропозиції» у головному меню; введена вручну команда `/news` також відкриває керування підпискою. Стан підписки зберігається після очищення чернеток і перезапуску. Команда `/cancel` («Скасувати чернетку») з’являється лише в чаті клієнта з активною чернеткою; після надсилання, підтвердженого скасування або очищення простроченої чернетки вона прибирається. `/status` і `/news` під час заповнення спершу пропонують продовжити чи скасувати чернетку, зберігаючи відповіді. Оновлення меню проходять через чергу повторних спроб і відновлюються після перезапуску. Після розгортання `configure-menu` оновлює стандартне меню; індивідуальне меню наявного чату оновиться після наступної взаємодії, наприклад `/menu`. Команда `/start` прихована зі списку, але працює через початкову кнопку Start у Telegram або при введенні вручну.

Сервіс відмовиться запускатися, якщо у бота вже налаштовано webhook; він не видаляє його автоматично. Один файл бази обслуговує один процес. База прив’язується до Telegram ID бота, щоб не змішати клієнтів і фото різних ботів.

## Попередній локальний режим: запуск у Docker

```powershell
docker compose -f compose.telegram.yaml build telegram-bot
docker compose -f compose.telegram.yaml up -d telegram-bot
docker compose -f compose.telegram.yaml logs --tail 50 telegram-bot
```

Проєкт Docker — `vector-erp`, образ — `vector-erp:telegram-bot`. База знаходиться в окремому томі `telegram-data`. Контейнер працює без root, без опублікованих портів, із файловою системою образу лише для читання. Файл `.env.telegram` обов’язковий; токен не потрапляє до build context чи образу.

Через спільну назву проєкту Compose може назвати наявні контейнери ERP «orphan containers», коли використовується лише файл бота. Це сервіси з основного `compose.yaml`; не додавайте `--remove-orphans` до команд бота.

Локальний Python і Docker використовують різні бази. Команди керування потрібно виконувати там, де працює потрібний екземпляр. Не запускайте два різні екземпляри з одним токеном. Для зупинки:

```powershell
docker compose -f compose.telegram.yaml stop telegram-bot
```

## Робота зі зверненнями у локальній копії

Після підтвердження клієнтом заявка й повідомлення для команди записуються однією транзакцією. Команда отримує номер, тему, відповіді, контакт, час створення UTC та фото. Номер заявки — послідовний ідентифікатор запису, а не декоративна нумерація.

Локальна черга доступна через CLI на комп’ютері із сервісом:

```powershell
python -m services.telegram_bot list-requests
python -m services.telegram_bot show-request 1
python -m services.telegram_bot set-status 1 in_progress
python -m services.telegram_bot set-status 1 closed
python -m services.telegram_bot health
python -m services.telegram_bot retry-failed
```

Статуси: `new`, `in_progress`, `closed`. Ці команди не надсилають повідомлень клієнту. `show-request` показує персональні дані й стан сповіщень; використовуйте його лише в робочому середовищі відповідальних працівників. У Docker, наприклад:

```powershell
docker compose -f compose.telegram.yaml exec telegram-bot python -m services.telegram_bot list-requests
docker compose -f compose.telegram.yaml exec telegram-bot python -m services.telegram_bot health
```

`health` показує кількість заявок і повідомлень за статусами, але не є перевіркою доступності Telegram. Ненадіслані повідомлення зберігаються й повторюються з паузою; враховується Telegram `retry_after`. Після постійної помилки або 12 спроб повідомлення переходить у `failed`. Виправте причину, перевірте `health` і запустіть `retry-failed`. Недоступність чату команди не блокує підтвердження клієнту: заявка вже є в локальній черзі.

Заявка створюється один раз на чернетку. Доставка повідомлень має семантику «принаймні один раз»: якщо процес завершився після відповіді Telegram, але до запису результату, повідомлення може повторитися. Номер заявки дає змогу розпізнати повтор. Старі callback-відповіді не повторюються через CLI.

## Дані та оновлення контенту

- Бот не завантажує сайт під час розмови. `content.json` містить джерела, дату перевірки, категорії, повідомлення, запитання та кнопки.
- Після зміни сайту перевірте відповідні тексти, внесіть зміни та оновіть `reviewed_at`. Для робочого бота запустіть тести Worker та `npx wrangler deploy`. Для окремої локальної копії перезапустіть Python-процес або перебудуйте Docker-образ. Під час роботи з активними чернетками зберігайте ідентифікатори та порядок полів сценаріїв.
- Ціни, характеристики й асортимент клієнт переглядає на сайті. Бот не підтверджує залишок, сумісність деталі, гарантійність випадку чи право на повернення автоматично.
- Телефони публікуються без назв відділів через розбіжність між сайтами. Графік роботи й видачі товарів наведений окремо. Тарифи перевізника та платіжні реквізити не копіюються.
- До відправлення деталі звернення знаходяться в чернетці; клієнт бачить пояснення перед кнопкою підтвердження. Контактні поля додатково зберігаються в постійному профілі для наступних звернень. Чернетки без активності очищаються через сім днів. Скасування прибирає чернетку з поточної сесії; профіль залишається.
- Фото зберігаються як Telegram `file_id` і `file_unique_id`, а не локальні файли. Команда отримує копії фото через того самого бота. Локальний архів оригіналів фото в MVP не передбачений.
- Завершені заявки автоматично не видаляються. Доступ до бази та групи команди надається лише відповідальним працівникам; резервні копії містять ті самі персональні дані.
- Тексти доставлених вихідних повідомлень прибираються з outbox, заявки залишаються основним записом. Невдалі/очікувані повідомлення зберігають тіло для повтору. Старі записи успішної доставки очищаються через сім днів.
- Операційні логи не містять токенів, телефонів і текстів звернень. Ліміт — 30 дій на хвилину та 5 нових заявок на годину від одного клієнта.

Для узгодженої резервної копії SQLite зупиніть сервіс перед копіюванням бази або використайте SQLite backup API; не копіюйте лише основний файл активної WAL-бази. У Docker резервуйте окремий том бота.

## Перед першим запуском для клієнтів

Призначте відповідальних за чергу та перевірте справжнім тестовим зверненням: текст, фото, отримання командою, повторну кнопку надсилання й контакт для дзвінка. Тести без мережі не підтверджують права конкретного Telegram-акаунта.

WhatsApp, Viber, онлайн-оплата, синхронізація з ERP, живі залишки, персональне відстеження замовлень і операторський чат залишаються наступними етапами. Модуль сценаріїв відокремлений від Telegram API для подальшого повторного використання правил і контенту.
